## 项目背景

本项目针对汽车排气管相关零部件的外观检测需求，使用工业相机进行图像采集，并结合 OpenCV 图像处理与 AI 缺陷检测模型，对指定区域进行自动检测和判定。

项目主要使用 C++ 和 AI 进行开发，实现从图像预处理、检测区域提取、AI 推理到检测结果输出的完整视觉检测流程。

## 检测流程

整个视觉检测流程可以概括为：

```text
工业相机
    ↓
原始图像
    ↓
图像 rulebase 处理
    ↓
检测区域提取
    ↓
AI 缺陷检测
    ↓
Detection Zone / Score
    ↓
结果判定
    ↓
OK / NG
```

C++ 主要负责图像前期处理以便输入合适的图像数据到 AI，AI 模型负责对指定区域进行缺陷检测。

## 工业拍摄环境设计

### 相机与光源选定

工业视觉检测的准确性不仅取决于后续的图像处理和 AI 模型，图像采集质量同样会直接影响最终的检测结果。

为了获得适合缺陷检测的稳定图像，本项目在前期验证阶段对不同的相机和照明方案进行了比较和验证。由于检测对象为汽车排气管零部件，产品尺寸较大，客户对 cycling time 也有限制（10s - 一个产品从拍摄开始到检测结果显示），同时存在金属表面反光、曲面结构以及不同类型缺陷等问题。使用区域相机和条形面型等光源，难以满足检测时间和缺陷对比度等要求。

因此，考虑到需要超高分辨率、高速连续成像以及大幅面检测，最终采用 NED 线阵相机（Line Scan Camera）进行图像采集，并根据不同缺陷的成像特征搭配 LEIMAC 的线性 Dome 照明和角形照明（Angle Illumination）。

```text
NED 线阵相机
       ↓
产品连续运动 / 旋转
       ↓
逐行采集图像
       ↓
完整产品图像
```

在光源方面，根据实际检测区域分别选择不同的照明方式：

| 照明方式       | 主要特点                                         | 适用场景                         |
| -------------- | ------------------------------------------------ | -------------------------------- |
| 线性 Dome 照明 | 提供较均匀的面状照明，降低部分金属表面的直接反光 | 需要观察整体表面状态的缺陷       |
| 角形照明       | 从特定角度照射产品表面，增强局部表面变化         | 对表面凹凸、附着物等缺陷进行突出 |

最终根据不同检测对象和缺陷特征，分别选择合适的照明条件，而不是使用单一光源覆盖所有检测项目。

### Hardware Trigger

由于本项目的 Cycling Time 较为紧张，并不需要让产品完整旋转一周进行图像采集，而是根据不同检测区域的角度位置，在指定的旋转范围内进行拍摄。

针对刻印部检测区域，只有产品旋转到特定角度范围后，该区域才会进入相机的有效拍摄范围。因此，需要通过 Hardware Trigger 控制相机的开始采集和停止采集时机。

```text
产品开始旋转
    ↓
旋转到指定角度
    ↓
开始 Hardware Trigger
    ↓
线阵相机连续采集
    ↓
完成目标区域拍摄
    ↓
停止 Hardware Trigger
    ↓
结束旋转
```

相比让产品完整旋转一周，这种方式可以减少不必要的旋转和图像采集时间，从而缩短整体 Cycling Time。

## 检测算法敲定

在确定相机、光源以及拍摄条件后，需要根据实际检测对象和缺陷特征，提前制定整体的检测算法方案。

工业视觉检测并不是所有缺陷都适合使用同一种方法进行检测。因此，在正式进行程序开发之前，需要先分析各个检测区域的图像特征，并判断哪些部分可以通过传统图像处理解决，哪些部分需要引入 AI。

本项目中，汽车零部件为金属材质，产品表面除了实际缺陷之外，还存在污点、划痕、纹理以及反光等正常特征。

如果仅使用固定 Threshold、面积、形状等 Rule-based 图像处理方法进行缺陷判定，正常区域中的部分特征可能会被误判为 NG，从而产生较多过检。

因此，本项目采用 **Rule-based 图像处理 + AI** 的组合方式。

其中，Rule-based 图像处理主要负责：

- 检测区域定位
- Template Matching / Mask 处理
- 文字位置检测
- 无关区域排除

AI Model 则主要负责对传统图像处理难以通过固定规则稳定判断的缺陷进行检测。

### 不同检测区域的算法方案

根据检测对象的不同，最终采用两种不同的检测流程。

#### 圆周熔接部、端部、座面、ボス穴

这些区域首先通过 Rule-based 图像处理提取对应的检测区域，然后将提取后的区域直接输入训练好的 AI Model 进行缺陷判定。

```text
原始图像
    ↓
Rule-based 图像处理
    ↓
检测区域提取
    ↓
AI Model
    ↓
Detection Zone / Score
    ↓
OK / NG
```

#### 刻印部

刻印部的检测流程与其他区域有所不同。

首先使用 Rule-based 图像处理对刻印文字的位置进行检测，判断文字整体位置是否处于规定范围内。

文字位置ずれ属于明确的位置关系问题，因此不需要使用 AI，而是直接通过 Rule-based 图像处理进行判定。

如果文字位置判定正常，则进一步提取刻印文字区域，并将提取后的图像输入对应的 AI Model，对其他刻印缺陷进行检测。

```text
原始图像
    ↓
Rule-based 图像处理
    ↓
刻印文字位置检测
    ↓
文字位置是否正常？
    │
    ├── NG → 文字位置ずれ
    │
    └── OK
          ↓
      提取刻印文字
          ↓
       AI Model
          ↓
Detection Zone / Score
          ↓
      OK / NG
```

AI Model 主要负责检测：

- 文字キズ
- 文字欠け
- 文字ずれ
- 2重打刻
- 文字うすい
- スパッタ

因此，刻印部并不是单纯使用 AI 进行所有缺陷判断，而是根据不同缺陷的特征选择合适的检测方法。

最终检测架构

综合各检测区域后，本项目形成了 **Rule-based + AI** 的混合检测架构。

```text
                         原始图像
                            ↓
                  Rule-based 图像处理
                            ↓
              ┌─────────────┴─────────────┐
              ↓                           ↓
        检测区域提取                  刻印位置检测
              ↓                           ↓
          AI Model                  位置是否正常？
              ↓                     ┌─────┴─────┐
     Detection Zone / Score         ↓           ↓
              ↓                    NG          OK
            OK/NG                    ↓           ↓
                              文字位置ずれ    提取刻印文字
                                                ↓
                                             AI Model
                                                ↓
                                      Detection Zone / Score
                                                ↓
                                              OK/NG
```

## C++ 图像前期处理

采集到原始图像之后，需要根据后续算法的 input 要求进行图像预处理。

主要处理内容包括：

- 灰度化
- 图像尺寸调整
- template matching, mask 方法进行检测区域抽取

图像预处理主要目的是：
（1）减少无关区域对检测结果的影响
（2）降低后续处理的计算量，减少检测时间

对于不同的检测区域，以下区域需要通过template matching 或 mask 方法进行提取。

- J61 刻印部
- J62 座面
- J62 刻印部

## AI 模型训练

使用 RoxyAI 进行缺陷检测模型的训练，并将训练完成的模型应用于 C++ 检测程序。

训练过程中，需要准备正常品和缺陷品图像，并对缺陷区域进行 annotation。

训练数据主要包括：

- 正常品
- 缺陷品

模型训练完成后，对输入图像进行推理，并输出检测结果。

主要结果包括：

- Detection Zone
- Detection Score
- 缺陷位置
- 缺陷判定结果

根据 Detection Score 与设定的阈值，可以进一步判断当前区域是否存在缺陷。

最终输出：

- J61 & J62 圆周熔接部 AI 模型
- J61 刻印部 AI 模型
- J62 刻印部 AI 模型

- J61 & J62 端部 AI 模型
- J61 & J62 座面 AI 模型
- J61 & J62 Boss穴 AI 模型

## C++ 和 RoxyAI Inspect Server 接口连接

在完成图像处理以及 RoxyAI 模型训练后，需要将训练完成的模型实际部署到 C++ 检测程序中。

本项目通过 RoxyAI Inspect Server 提供 AI 推理功能，C++ 程序负责准备输入图像、调用 Inspect Server 进行推理，并接收模型返回的检测结果。

整体结构如下：

```text
C++ 检测程序
      │
      │ Input Image
      ↓
图像预处理
      │
      │ ROI / Resize / Padding
      ↓
RoxyAI Inspect Server
      │
      │ AI Inference
      ↓
Detection Result
      │
      │ Zone / Score / Position
      ↓
C++ 后处理
      │
      ↓
OK / NG
```

## AI 模型优化

在 AI 模型 Sample Data 的检测结果中，部分检测区域仍存在过检（False Positive）和漏检（False Negative）情况。

其中，过检是指实际为 OK 的区域被 AI 模型判定为 NG；漏检则是指实际存在缺陷的区域被 AI 模型判定为 OK。

目前主要观察到以下区域存在过检和漏检：

| 检测区域   | 检测问题                                             |
| ---------- | ---------------------------------------------------- |
| 圆周熔接部 | 微小穴、割れ等正常特征被误判为缺陷，同时存在部分漏检 |
| 端部       | スパッタ付着过检、漏检                               |
| 座面       | スパッタ付着过检、漏检                               |
| ボス穴     | スパッタ付着过检、漏检                               |

### 原因分析

对检测结果进行分析后，主要考虑以下原因：

- Sample Data 数量不足
- 正常区域存在与缺陷相似的纹理或结构

特别是部分 OK Sample 中存在与目标缺陷相似的纹理或结构，如果直接将这些 Sample 加入训练数据，AI Model 可能会将这些特征学习为正常特征，从而影响缺陷的识别能力。

因此，在优化过程中不仅需要关注 Sample Data 的数量，还需要对 Sample Data 的内容进行筛选。

### 优化方法

针对检测过程中发现的过检和漏检，对相关 Sample Data 进行分析，并对训练数据进行调整。

```text
Sample Data
    ↓
AI Model Training
    ↓
测试
    ↓
发现过检 / 漏检
    ↓
确认问题区域
    ↓
分析 OK / NG Sample
    ↓
筛选与缺陷相似的 OK Sample
    ↓
移除不适合的 Sample
    ↓
重新训练
    ↓
再次测试
```
